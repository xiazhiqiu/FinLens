# P4 问题清单：把「真·多 Agent 财报分析」跑通

> **唯一目标**：让「财报分析多 agent 系统」里的每个 agent，都能在上下文预算内拿到它需要的年报知识，
> 并完成分析 / 撰写 / 复核。
> L1 / L2 / L3 / 装配器 / 工具 / facts 全部是**手段**，不是目标。评价标准只有一条：
> **端到端分析跑得通、质量够、成本撑得住。**
>
> 处理方式：按编号逐项推进，每项做完即验收（测试 + 真实年报验证），不做半成品。
> 状态图例：⬜ 待办 / 🟡 进行中 / ✅ 完成

---

## 〇、先说清「真·多 Agent」的边界（避免自欺）

按既定架构（确定性引擎 + LLM 受限叶子 + 合规判定 LLM 零参与）：

| 节点 | 性质 | 是否「agent」 |
|---|---|---|
| Supervisor | LLM 路由决策 | ✅ agent（协调能力，非合规判定） |
| ReportExtractor | 确定性解析 + L1 | ❌ 确定性节点（**应当**如此） |
| DataRetriever | 确定性取数（akshare/tushare） | ❌ 确定性节点（**应当**如此） |
| FinancialAnalyst | LLM + 工具 | ✅ agent |
| ReportWriter | LLM + 工具 | ✅ agent（**待接**） |
| Reviewer | LLM + 工具 | ✅ agent（**待接**） |

结论：**真 agent 只有 4 个**。目前只有 Analyst 真正持有工具 → 「多 agent」只兑现了 1/3。
这就是 A 组要解决的问题。

## A 组｜主战线：把多 Agent 接完（P4 本体）

### A1 ✅ Writer 接 `pdf_context` + 上下文工具
- **问题**：Writer 仍消费 `pdf_summary`（旧 eager 压缩产物，丢主体/丢期间/丢表格精度），
  L1/L2 的成果到写报告这一步被绕开——**最终报告仍踩在旧压缩的精度天花板上**。
- **证据**：`src/agents/report_writer.py`（消费 pdf_summary，截断到 2000）
- **解法**：`USE_MULTILEVEL_COMPRESSION=true` 且 `pdf_l1` 就绪时，
  Writer 走「预算装配 + 3 工具（fetch_context/query_fact/search_section）」，
  写某段时按需取该段表格/数字；沿用 Analyst 的有界工具循环 + `tool_call_history` 审计。
- **验收**：flag 开启下 Writer 能取到章节原文与结构化数字；工具调用有留痕；产物不比旧路径差。
- **完成（2026-09-03）**：`_multilevel_writer_run` 落地——装配时 **l2/l3 直接读 state**
  （Analyst 写回的缓存，Writer 侧零构建，A3 读侧前提）；修订模式同样挂工具（核对反馈数字）；
  LLM 失败产降级报告不回退二次调用；成功后处理收敛为 `_finalize_report`（新旧两路共用，
  免责声明/来源表/审查标注/版本脚注行为不变）。测试 `tests/test_a1_writer.py` 6 条
  （门控新旧两路/l2l3 复用/审计留痕/修订模式/降级），全量 114/114。

### A2 ✅ Reviewer 用 `query_fact` 核验报告数字（多 agent 分工真正成立）
- **问题**：Reviewer 只做文本层审查（数据一致性/过度断言/维度完整），**没有数字核验能力**——
  报告里写「营收 204.42 亿」到底对不对，没人查。
- **价值**：① 让「一个写、一个查账」的分工真实成立 ② 落在银行可审计/可解释红线上
  ③ 是用户「保持 agent 形态」决策的最佳注脚。
- **解法**：给 Reviewer 挂 `query_fact`（+ 可选 `verify_citation` 校验 `[P n]` 页码是否真实存在）。
- **验收**：报告数字与事实表不符时，Reviewer 能产出具体的 revise 反馈（写明期望值 vs 实际值）。
- **完成（2026-09-03）**：`reviewer.py` 新增 `_FACT_CHECK_GUIDE`（核验职责进 prompt：数字不符
  必须写「报告值 X vs 事实表值 Y [溯源]」）+ 门控分支（`USE_MULTILEVEL_COMPRESSION and
  pdf_l1.facts`，facts 为空不挂工具）；挂全部 3 工具（fetch_context 可校验页码引用真实性）；
  审计回调 agent="reviewer"；合规预检/CRITICAL 强制 revise/熔断/JSON 判定格式全部不动。
  verify_citation 未做独立工具（页码校验折叠进 fetch_context 指引，独立工具留给 C 组）。
  测试 `tests/test_a2_reviewer.py` 6 条（含熔断优先于新链路、facts 门控、降级留痕），全量 120/120。

### A3 ✅ 多 Agent 共用 L2 缓存
- **问题**：`pdf_l2` 目前只有 Analyst 用；Writer/Reviewer 接入后若不复用，会重复压缩。
- **解法**：`pdf_l2` / `pdf_l3` 已在 state，Writer/Reviewer 直接读；跨 agent、跨修订轮零重压。
- **验收**：修订循环第二轮起 L2 新增构建数 == 0。
- **完成（2026-09-03，与 A4 合并执行）**：读侧在 A1 已实现（Writer/Reviewer 装配直读 state）。
  **验收测试抓到真 bug**：`_multilevel_analyst_run` 成功分支 return 漏写 `pdf_l2`/`pdf_l3`
  （错误分支都有，主路径没有）→ 修订第二轮必重压。已修复。测试 `test_a3_a4.py`：
  单元级（同批章节二次构建新增 == 0）+ 链路级（修订第二轮 compress_section 调用数 == 0）。

## B 组｜事实质量（穿插做，一行级修复优先）

> 定位：让目标「达成得可信」，不是目标本身。按性价比排序，A 组推进中顺手清掉。

### B1 ✅ 编号行误抽（**已实证**）
- `metric="0" = 16.0`（p45）：某表行首列是编号，被当成科目。
- 解法：跳过纯数字行标签；验收：真实年报中此类垃圾事实 == 0。
- **完成（2026-09-03）**：`_ROW_NUM_RE` 覆盖 `'(A)'/'0'/'(ii)'/'1.'` 全部 8 条实证垃圾；真实年报残留 == 0；
  误伤检查通过（收益/毛利/存貨 等短科目保留）。

### B2 ✅ 会计括号负数解析为正
- `(1,234)` → 1234 而非 -1234（**符号反了，方向性错误**）。
- 解法：`parse_number` 识别括号负号；验收：单测覆盖 `(1,234) → -1234`。
- **完成（2026-09-03）**：根因是原正则 group 索引错（`m.group(2)` 取到 `%` 组，负号从未生效）。
  重写为成对括号独立分支 + 残缺括号丢弃；真实年报 79 条括号负数全部转负、0 条残留。

### B3 ✅ % 量纲剥离
- `12.3%` → value=12.3，比率被当绝对值用。
- 解法：Fact 增加 `is_pct` 标记（raw 保留原文）；验收：单测。
- **完成（2026-09-03）**：表格/文本两层 facts 均带 `is_pct`；真实年报 10 条比率事实全部标记。

### B4 ✅ `合计/小计` 行未标记
- 小计/合计行与明细混在 facts 中，可能被重复计量。
- 解法：行标签命中「合計/合计/小計/小计/總計/总计」时标 `is_subtotal=True`；验收：单测 + 真实抽查。
- **完成（2026-09-03）**：简繁双套规则（含「流动资产合计」类包含命中）；标记不改抽取，
  由下游决定是否剔除。已知语义：同表多条「小計」因 dedup_key 同键只留首条（先到先得，既有设计）。

### B5 ✅ 期间精度不足
- 只抓年份 → 半年报列「2024年6月30日」也归成 `FY2024`，与年报列 dedup 错并。
- 解法：列头含月份时归一为 `2024H1` / `Q1..Q4` 等细粒度期间；验收：单测。
- **完成（2026-09-03）**：`normalize_period` 按日期精度归一——12-31→FY / 6-30→H1 /
  3-31→Q1 / 9-30→Q3 / 其他明确日期→`YYYY-MM-DD`（精确标签绝不并入 FY）；
  「止六個月/上半年」措辞归 H1。dedup 错并单测通过（半年列+年末列同表出两条独立事实）。

### B6 ✅ 常用科目别名小表（规则版）
- `非臨床研究服務` ≠ `营业收入`，按「营业收入」查不到（LLM 别名归一是受限叶子，默认关）。
- 解法：规则小表（营业总收入/收益/收入/营收 → 标准名），可审计；验收：单测。
- **完成（2026-09-03）**：`_METRIC_ALIAS` 精确整串匹配表（繁/简/口语/港股 IFRS 口径，
  含 `淨資產→股东权益合计`；A股 CAS 表述 `归属于上市公司股东的净利润→归母净利润` 等）；
  fact 新增 `metric_std`（原 metric 保留溯源），`dedup_key` 用标准名
  → 繁简变体正确合并；`query_fact` 查询侧同步归一（查"营业收入"可命中"總收益"）。
  **A股适配（furui 实测追加）**：A股「主要会计数据」表单位内嵌在科目名尾部（`营业收入（元）`），
  新增 `split_metric_unit` 剥离行级内嵌单位（非货币括号如 `（注）`/`（人）` 不误伤），
  行级单位优先于表级——修复后 furui 归母净利润从「未抽到」变为表格级 0.9 置信
  （FY2024 219,215,799.89 元），营业收入从文本级 0.6 升为表格级 0.9。
  真实年报：joinn 命中 8 条（總收益/總資產/總負債/淨資產）。

### B7 ✅ 数值勾稽校验
- 无一致性检查（如 资产 = 负债 + 权益）。
- 解法：确定性规则 + 容差（抄 Agentic FinSearch 口径 `max(0.01%×期望, 0.005)`），
  命中打 `identity_checked=True`，不符**告警降置信**不静默；验收：单测 + 真实年报（允许「无匹配」）。
- **完成（2026-09-03）**：新模块 `identity_checker.py`（资产总计 = 负债合计 + 股东权益合计；
  单位已知先折算到元、口径不明跳过；不符降置信 ×0.6 + `identity_mismatch` 标记；记录入 L1 stats）。
  **真实年报双验证全 PASS**：joinn FY2023/FY2024（9,396,152 = 1,316,964 + 8,079,188）、
  furui 期初/期末。验收中真抓到一个错：furui 期末权益因**数字内部空格**（`'2,383, 553, 485.39'`）
  解析失败 → dedup 落到母公司报表值 → 勾稽 FAIL 降置信——正是设计目标（宁误报不漏报），
  随后修 `parse_number` 去内部空白（furui facts 1457→1488）。

### B8 ✅ 计量单位解析（unit 邻接）
- 多数 MinerU caption 为空（表题是表格前独立 text item），unit 基本为空 → 裸大数。
- 解法：用**表格前邻接文本**解析（此前整章正则启发式误命中率高已回退，宁缺毋滥）；验收：真实年报 unit 命中率与正确率抽检。
- **完成（2026-09-03）**：三级解析链（caption/footnote → 邻接文本严格标记 → **网格单位行**）。
  邻接文本须带 `單位：`/`（）` 明确标记（无标记不猜，防 P1 千元误标百萬元教训）；
  网格单位行为港股实测发现（单位在表格第 2 行 `<td>人民幣千元</td>`，joinn t_093/t_021）。
  真实年报：furui 301/393 表有单位（A 股 caption 普遍带），joinn 0→26 表（全部 `人民幣千元`），
  并使 B7 单位折算生效。

### 已定决策（讨论中收敛）
- ❌ **取消「查询宽度分类」**：系统目标是端到端生成报告，无轻量查数字场景（早前误将 FinGLM
  竞赛 QA 场景映射进来，属伪需求）。Supervisor 保持现状。
- ✅ **A股十节 → 5 领域 agent**：①经营分析(MD&A 第三节) ②财务数据(第二节主指标+第九/十报表,
  附注 ~90k 超窗, 以 query_fact 查 facts 为主通道) ③治理与ESG(四/五节) ④重要事项与股东(六/七节)
  ⑤公司概览与风险(一/二节内风险+尾备查)。第八/十节多为空模板不配独立 agent。
- ❌ **不做「一章一 agent」map-reduce**：reduce 层原样继承压缩问题（信息守恒），且跨章勾稽
  推理被切碎（仅留并行化 L2 构建为有价值部分）。
- ⚠ **不采纳「全 L2 / 纯目录+工具」**（虽 token 装得下：furui 全 L2 仅 ~12k/joinn ~21k）：
  表格是 L2 压缩盲点（分产品营收/前五大客户等表格退化指针）+ LLM 版 L2 精度未验（C3 挂着）+
