# 2026-09-01

## 项目摸底：FinScope（D:\develop\财报分析系统）

- 定位：基于 LangGraph 多智能体协同的金融研报智能分析系统（Python 3.11-3.13，Streamlit 前端）。
- 架构：Supervisor（LLM 决策 + 规则回退）+ 4 子 Agent（report_extractor / data_retriever / financial_analyst / report_writer），StateGraph 条件路由，子 Agent 完成后返回 Supervisor 循环决策，iteration_count ≥ 15 硬熔断，单 Agent 连续调用 ≥3 次强制终止。
- 数据层：Tushare（优先）+ AkShare 降级双数据源；MinerU/PyMuPDF PDF 解析；SQLite checkpoint（SqliteSaver，失败回退 InMemorySaver）。
- 企业级模块（src/security、compliance、audit，try/except 可选导入，默认开启）：InputGuard 输入防护（SQL注入/XSS/prompt注入）、ContentFilter 输出合规过滤、RegulationEngine 监管规则、ChineseWall 信息隔离墙、RBAC 权限、JWT/APIKey 认证、AES 加密、审计日志（HashChain 不可变存储、DataLineage 血缘追踪）。
- 前端：frontend/app.py（Streamlit + 登录页 + Agent 执行时间线组件 step_progress.py）。
- 运行：`streamlit run frontend/app.py` 或 `python src/run_cli.py "查询"`；无 LLM Key 时全链路规则回退生成模板报告。
- 注意：LLM Provider 可配 DeepSeek/OpenAI/Ollama，默认 deepseek；docker-compose 企业部署（finscope + redis + nginx），依赖 JWT_SECRET/AES_ENCRYPTION_KEY 等环境变量。

## 银行内部使用定位评估（关键结论，已 grep 交叉验证）

- **接入主流程的仅 3 个企业级组件**：InputGuard（financial_graph.validate_input）、ContentFilter（filter_output）、AuditLogger（graph+supervisor 调用）。
- **AuditLogger._log_to_file() 是空实现（pass）**，注释自述"实际应使用 ImmutableStore"→ 审计只有内存+控制台，无文件落盘闭环。
- **未接入主流程的 6 个组件（写了没接线）**：ImmutableStore/HashChain、DataLineage、RegulationEngine、ChineseWall、RBACManager、JWTAuth/TokenManager、AES256Encryption——仅存在于模块定义 + __init__ 导出 + 单测。
- 合规判定=确定性正则（CSRC-001~005/SSE-001），LLM 零参与（符合红线），但 RegulationEngine 未接入 graph 输出链路，实际只有 ContentFilter 一层。
- 数据兜底三级降级 Tushare→AkShare→内置模拟数据（data_source 有标注，可辩护但银行场景需显式阻断）。
- 可解释性=步骤级（supervisor reason + stream 回放）有，结论级/数字级溯源无（report 无 citation 绑定，DataLineage 未接入运行时）。
- 测试=12 个企业级模块单测（test_enterprise.py），无 graph 全链路集成测试。
- 简历口径：可写"LangGraph 5-Agent 编排 + 动态调度/硬熔断/双源降级 + 确定性合规（LLM 零参与）"；不可写"企业级可审计防篡改银行系统"（审计闭环缺失）。
